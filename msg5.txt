docs: register D-032..D-036 and stop marking unverified work as done

DEVIATIONS.md gains the five divergences this round introduced or had to name:

- D-032 the write is validated structurally before it lands, so "never silently
  corrupts" is a statement about the RESULT (SPEC §4.1.1 / §5.5.5 / R2)
- D-033 the sidecar returns a timeout immediately instead of waiting for a reply
  the running cell cannot send, and Windows interrupt unavailability is stated
- D-034 the connection file is created with mkstemp (atomic, 0600, unpredictable
  name) rather than a predictable path in a shared temp directory
- D-035 a transient Windows sharing violation on rename is retried before
  `notebook_locked` is reported
- D-036 `cell_selector` has a length bound for the same reason §4.1.12 bounds
  arrays: the parse errors echo it back

D-024 is corrected rather than extended: the strict schemas from v3 made the
tool-layer rejection unreachable, so the entry now describes passthrough +
tool-layer rejection and the honest trade (the advertised schema no longer says
`additionalProperties: false`, which it never actually enforced).

REVIEW-FIX-STATUS.md gets a fourth-round section that separates the two kinds of
work: the 🔴 that was fixed, and the capability that should have caught it. It
also stops over-claiming: unverified or undone items are now ⬜/⚠️ with the
reason, because this round showed two ways a ✅ can be wrong — judging a fix by
sampling the wrong lines (QUAL-1) and marking something "changed" as "verified"
(`prepack`, which had never been run without pnpm on PATH).

README states the four consequences a user can actually observe: interrupt
usually does not work on Windows, so a timeout relies on the kernel shutdown;
every write is validated before it lands; the connection file's location, mode
and unpredictability; and that an unknown argument is an error rather than a
silent default.

AGENTS.md §9 gains the rule this round paid for — assertions may not speak only
the product's own dialect; an external authority (nbformat, a real client) must
judge compliance, fixtures included, and format problems must be found with a
parser rather than by sampling.
