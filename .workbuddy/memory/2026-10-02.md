## 关键踩坑（值得记住）

1. **sidecar 单线程协议死锁**：exec_cell 在途时 interrupt op 在 stdin 排队永远无法及时处理——I13/I16 挂 30s+。修复：sidecar 每请求一个工作线程（控制类 op 可插队）。
2. **jupyter_client 8.6.3 无 kernel_cmd 参数**：start_kernel(**kw) 的 kw 直通 Popen；argv 覆盖要原地改 `km.kernel_spec.argv`。
3. **shell/iopub 消息串扰**：wait_for_ready 的 kernel_info_reply 残留在 shell 队列；必须按 parent_header.msg_id 过滤 + 双通道 drain。
4. **conda 环境的 python 在 `<env>/python.exe`**（非 Scripts/），`dirname(dirname())` 算 prefix 会错一层——`pythonPrefix()` helper 处理两种布局。
5. **Windows 锁定文件**：Node 的 fs.open 自带 FILE_SHARE_DELETE 锁不住 rename；要 CreateFileW dwShareMode=0。且 EBUSY 首先发生在**备份的 copyFile**而非 rename——备份路径也要映射 notebook_locked。
6. NodeNext ESM：源码 import 必须写 `.js` 扩展（tsc 不改写）；SDK inputSchema 只收 zod shape（zod 是 sdk 的 peerDependency，已声明 D-005）。
7. vitest 集成测试 `fileParallelism: false`：真实 kernel 的时序用例在文件并行下不稳定。
