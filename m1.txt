fix: scope the write gate to the cells this write is responsible for

The v4 gate checked the whole DOCUMENT, which meant it also judged the user's
INPUT. A file that already contained something this tool would not write — a
`display_data` without `metadata`, exactly what third-party tools and older
versions emit — made every `notebook_edit` and every `notebook_run` fail forever
with `selfcheck_failed`, and the error pointed at a cell the caller had never
touched. Reading worked, writing did not, and the only way out was to fix a file
by hand. Refusing to write protects the file but destroys the product
(review v5 GATE-1).

Scope now comes from the caller: the edit path passes the cells its ops changed,
the run path passes the cells it executed. A problem in a cell we are NOT
writing is carried forward verbatim and reported as a warning
(`notebook_preexisting_content`) through the same channel notebook_run already
uses for warnings, because a log line would inform the operator while leaving the
model — the actual consumer — believing the file is clean. A cell we ARE writing
is still refused if it carries a problem, and clearing that cell's outputs is
allowed: the gate must not punish a write that just removed the problem.

Two corrections to the rules themselves, both found by comparing against the
authority rather than against ourselves:

- GATE-2: `nbformat.validator` relaxes `additionalProperties` and accepts
  `unrecognized_output` for `nbformat_minor` above the schema it implements, so
  rejecting an unknown `output_type` there was a false positive on a VALID file.
  Above minor 5 the kind checks are relaxed the same way. An unknown `cell_type`
  stays a `parse_failed` — that is "cannot read it", not "read it and refuse to
  write it back", and the difference is pinned by a test.
- GATE-3: `execute_result.execution_count` was only checked for PRESENCE, so
  `"3"` passed while nbformat rejects it. Now it must be an integer or null.

The README stops claiming more than the gate does: it covers the shapes this
implementation can break, not "legality" in general (D-037 narrows D-032).
