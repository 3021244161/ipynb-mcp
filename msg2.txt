fix: prompt timeouts, reachable argument checks, and a linear framer

FID-6 — a timed-out cell waited 30 s for an `execute_reply` that cannot arrive:
the kernel is still running the cell, so there is nothing to reply. The wait had
no semantic value either — SPEC §4.7 rule 5's response IS the timeout, and the
detached execution's output is discarded by design. Measured: `timeoutMs=3s` on
`time.sleep(30)` cost 38 s. The sidecar now returns immediately, and the
transport margin shrinks to match (timeoutMs + the 5 s interrupt grace + slack).

The same investigation produced a fact the README now states plainly: on
Windows `interrupt_kernel()` needs a console event a stdio MCP server has no
console to deliver, so a `time.sleep` cell ignores the interrupt and runs to
completion while the tool has already returned `exec_timeout` and closed the
kernel. That shutdown is what actually reclaims the CPU (D-025), and the
platform limitation is documented rather than implied.

NEW-1 — the v3 fix made the unknown-argument rejection dead code. The schemas
were `.strict()`, so the SDK refused the request before the handler ran, which
also meant the SDK's error code replaced the `invalid_arguments` SPEC §4.1.12
names. Measured by the review: deleting the whole tool-layer whitelist kept the
suite green. Schemas now pass unknown keys through and the tool layer rejects
them, so the rejection is both reachable and correctly coded; the new test
covers all six tools and asserts the detail, and reverting the whitelist turns it
red.

ROB-10 (completion) — `#failureDetail()` returned the stderr tail INSTEAD of the
exit reason, so the symbolized Windows status code was computed and then thrown
away exactly when it mattered: the pyzmq abort writes to stderr, so the tail
always won and the review measured "symbolization 0% effective". Both halves now
travel together, and a sidecar-reported failure carries the exit facts when the
child is gone.

D-035 — `rename` retried on EBUSY/EPERM/EACCES for a bounded window before
reporting `notebook_locked`. Windows reports the same errnos for "another
process holds this file" and for two renames colliding; the second is transient,
and reporting it as a lock handed the model the one error it is told to stop and
ask the user about. Observed as a genuinely intermittent unit failure.

D-036 — `cell_selector` is capped at 4096 characters (rejected without echoing
the value). SPEC §4.1.12 bounds array arguments because the response would
otherwise scale with the input; a string the parse errors echo back is the same
surface.

FID/QUAL residue — `backup.ts` dropped a duplicate `[ipynb-mcp] warn` prefix that
doubled with the logger's, and `timeout_seconds` is declared as an integer.
Broadcast enums deliberately stay in the tool layer: a schema enum would make the
SDK return a protocol error, and U27 requires `invalid_arguments`.
