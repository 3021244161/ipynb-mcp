## Pre-merge corrections

Independent review reproduced two issues relevant to this release:

- Restart could overlook an old kernel whose startup was still pending. Both interpreter sessions could remain registered, and a full run could report the replacement while executing in the old environment. The registry now drains pending starts by notebook before shutdown, retires matching sessions and prevents new starts from bypassing shutdown. A shutdown epoch rejects probe or cleanup continuations from the retired lifecycle, including a shutdown that has already completed.
- Shutdown/restart marked an active background run failed without declaring its write-back facts pending. The existing cancellation contract now also applies here: raise `facts_pending` before abort, preserve completed-cell results and clear the flag only after final write-back facts arrive.

Seven deterministic regression cases failed before their corresponding corrections and passed afterward: same/changed interpreter replacement during startup; positive/negative liveness probes across replacement; cleanup outliving shutdown; and pending/final facts for shutdown and restart. They use real registry/run/write-back logic and SDK clients, substituting only interpreter discovery and the external transport. SPEC anchors: I9, I16, U24.
