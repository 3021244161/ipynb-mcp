## 已修复问题

| 范围 | 已确认的问题 | 修复与证据 |
|---|---|---|
| 启动配置 | 大整数被舍入，400 位整数可变成 Infinity 后通过校验 | 安全整数校验；U27 的 CLI / env / 有效边界用例 |
| 启动围栏 | Windows UNC 共享根目录未被拒绝 | 按 Windows 路径根判断；U11 共享根与子目录控制用例 |

| 写入安全 | 序列化或备份期间外部编辑被覆盖 | 临时文件准备完成后、每次 rename 前复检；U12 真文件修改回归 |
| 写入取消 | Windows rename 重试期间取消仍继续覆盖文件 | 每次重试观察 signal；I14 原文件与临时文件清理断言 |
| 编码保真 | 非法 UTF-8 被静默替换为 U+FFFD | 严格解码并返回 parse_failed；U1 四类坏字节与合法 Unicode 控制 |
| 大源码编辑 | 15 万行插入/替换触发函数参数数量上限 | 移除参数 spread；U2/U6 断言完整源码、行数、CAS |
| CAS 错误契约 | actual_truncated 缺失，邻接锚对象绕过 4000 字符上限 | 补回 SPEC 已有字段并限制邻接文本；U2/U6 保留完整重试哈希 |
| 选择器 | 非安全整数导致 i += 1 不前进；大区间先展开后检查边界 | 展开前校验安全整数与 notebook 边界；U13 边界回归 |
| full 模式 | 无效选择器被解释，而不是被忽略 | full 直接选全部 code cell；U13 变异恢复旧分支时用例失败 |
| 请求取消 | 未提供 progressToken 时 signal 丢失 | SDK 请求取消与 progress 解耦；I13 真 SDK / server / registry 驱动 |
| 请求收尾 | 同步成功/失败后残留 abort 监听器 | 两层监听器在 finally 中清理；I13 断言监听器数为零 |
| 响应预算 | 未配对代理字符被低估；文本第二次 JSON 转义未计入部分图片选择 | 按实际转义和图片封装计量；U24 与真 SDK 连续调用回归 |
| 拒绝载荷 | 大量顶层标量或多个短身份字段仍让 refusal 超预算 | 仅保留有限身份字段并校验合计字节；U24 两类载荷回归 |
| 截断事实 | completed / failed run 的 stream、单行 preview 被截短后标志仍为 false | 同步 flag 与实际截断位置；U21b 覆盖 executed、detail.executed、preview |
| 图片引用 | images=always 的 summary 图片引用为空；丢图后索引悬空 | summary 返回实际引用；最终响应清空遗漏引用、重编号；U26 |
| 图片物化 | 预算扣图、失败 run、尚未轮询的后台结果仍可能预先写盘 | 延迟到最终图片选择后物化；D-066 恢复 SPEC，U26 真文件断言 |
| 图片取消 | 最终写盘阶段忽略请求取消，继续写后续图片 | 保留已完成写入，停止未开始写入；I14 精确在两次真写盘间取消 |
| 图片警告 | 预算不足被误报为写盘/解码失败 | 预算扣图使用 output_truncated，真实失败使用 image_materialize_failed；U26 |

选择器的不安全整数循环由独立静态审查确认；没有在主服务中盲跑永久循环。其安全整数与范围边界测试已经证明判据生效。
